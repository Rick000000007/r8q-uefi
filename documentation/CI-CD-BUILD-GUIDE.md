# Project R8Q — GitHub Actions CI/CD Build & Operation Guide

**Target Hardware:** Samsung Galaxy S20 FE 5G (`SM-G781B` / `r8q`)  
**Platform SoC:** Qualcomm Snapdragon 865 (`SM8250` / Kona)  
**Target Architecture:** ARM64 / AArch64 (ARMv8.2-A)  
**Host Environment:** GitHub Actions `ubuntu-latest` (x86_64)  
**Document Revision:** 1.0.0  
**Status:** Authoritative Operational Guide  

---

## 1. Overview & Execution Modes

Project R8Q's build infrastructure is designed to execute autoritatively in GitHub Actions without requiring local hardware, flashing cables, or manual build steps.

Builds can be triggered in three modes:
1. **Automated Continuous Integration:** Triggered on every `git push` or `pull_request` affecting platform code.
2. **Manual Dispatch (Web UI / GitHub CLI):** Parameterized builds for testing specific configurations, DEBUG builds, or on-demand releases.
3. **Release Tagging:** Pushing a version tag (e.g. `git tag v1.0.0-terminal && git push origin v1.0.0-terminal`) automatically runs the complete build pipeline, executes all 116 tests, packages the distribution, and publishes the official GitHub Release.

---

## 2. Triggering Builds via GitHub Web UI

1. Navigate to the GitHub repository: `https://github.com/Rick000000007/r8q-uefi`
2. Click on the **Actions** tab in the top navigation bar.
3. In the left sidebar, select **R8Q Complete Platform Build Pipeline (Master)** (`r8q-complete-build.yml`).
4. Click the **Run workflow** dropdown on the right.
5. Configure the build parameters:
   - **Branch:** Select `master` (or your feature branch).
   - **EDK II & Application Build Profile:** Select `RELEASE` (optimized) or `DEBUG` (with verbose UART logging).
   - **Perform clean build from scratch:** Select `true` or `false`.
   - **Execute full automated regression & acceptance test suite:** Select `true` (recommended).
   - **Release Tag Version:** Enter desired release version string (e.g. `v1.0.0-terminal`).
   - **Publish official GitHub Release with distribution bundle:** Set to `true` if an official release should be published.
6. Click **Run workflow**.

## 3. Triggering Builds via GitHub CLI (`gh`)

Ensure `gh` is authenticated (`gh auth login`).

### 3.1 Trigger Full Release Build
```bash
gh workflow run r8q-complete-build.yml \
  --ref master \
  -f build_config=RELEASE \
  -f run_acceptance_tests=true \
  -f release_version=v1.0.0-terminal \
  -f publish_release=true
```

### 3.2 Trigger DEBUG Firmware & Boot Manager Build
```bash
gh workflow run build-firmware.yml --ref master -f build_config=DEBUG
gh workflow run build-boot-manager.yml --ref master -f build_config=DEBUG
```

### 3.3 Trigger FAT32 ESP Disk Builder
```bash
gh workflow run build-esp.yml --ref master -f build_config=DEBUG
```

### 3.4 Monitor Workflow Execution
```bash
# Watch active workflow runs
gh run list --workflow=r8q-complete-build.yml

# Stream live build logs
gh run watch
```

## 4. Downloading Build Artifacts

Artifacts are retained for 30 to 90 days depending on the component type.

### 4.1 Download via GitHub CLI
```bash
# List artifacts generated by the latest run
gh run view --log

# Download all artifacts from a specific run
gh run download <RUN_ID> -d ./r8q_artifacts

# Download only the compound boot image
gh run download <RUN_ID> -n r8q-complete-boot-img

# Download the LineageOS recovery flashable ZIP
gh run download <RUN_ID> -n r8q-recovery-installer-zip

# Download the full reproducible system distribution tarball
gh run download <RUN_ID> -n r8q-full-system-distribution
```

## 5. Local Reproduction Guide (Workstation Build)

To reproduce the exact GitHub Actions build environment on a local Linux workstation (Ubuntu 22.04+ or Debian 12 ARM64/x86_64):

### 5.1 System Prerequisites
```bash
sudo apt-get update
sudo apt-get install -y \
  gcc-aarch64-linux-gnu binutils-aarch64-linux-gnu build-essential \
  device-tree-compiler parted dosfstools mtools e2fsprogs debootstrap \
  cpio gzip tar python3 python3-pip python3-yaml git
```

### 5.2 Build Steps
```bash
# 1. Clone repository
git clone --recursive https://github.com/Rick000000007/r8q-uefi.git
cd r8q-uefi
export PROJECT_ROOT="$PWD"

# 2. Compile EDK II BaseTools and Platform Firmware
export WORKSPACE="$PWD/edk2"
export PACKAGES_PATH="$PWD/platform:$PWD/edk2"
export EDK_TOOLS_PATH="$PWD/edk2/BaseTools"
export PATH="$EDK_TOOLS_PATH/BinWrappers/PosixLike:$PATH"
export PYTHON_COMMAND=python3
export GCC5_AARCH64_PREFIX=aarch64-linux-gnu-

make -C edk2/BaseTools -j$(nproc)
cd edk2
build -p R8QPkg/R8QPkg.dsc -a AARCH64 -t GCC5 -b RELEASE
build -p R8QPkg/R8QPkg.dsc -m R8QPkg/Applications/Setup/Setup.inf -a AARCH64 -t GCC5 -b DEBUG
build -p R8QPkg/R8QPkg.dsc -m R8QPkg/Applications/BootManager/BootManager.inf -a AARCH64 -t GCC5 -b DEBUG
cd "$PROJECT_ROOT"

# 3. Build Kernel DTB and Validate Image
mkdir -p build
dtc -I dts -O dtb -o build/sm8250-samsung-r8q.dtb devicetree/r8q-live.dts
./scripts/build_kernel.sh

# 4. Generate FAT32 EFI System Partition (256 MiB)
./scripts/build_esp.sh

# 5. Assemble Compound Android Boot Image v2
python3 scripts/package_complete_boot_img.py

# 6. Package LineageOS Recovery ZIP
python3 scripts/package_recovery_zip.py \
  build/r8q-uefi-boot-complete.img \
  build/R8Q-Debian12-Recovery.zip

# 7. Package Full System Distribution Tarball
python3 scripts/package_full_system.py

# 8. Run Full Acceptance & Regression Test Suite
python3 -m unittest discover -s tests -p "test_*.py"
```
