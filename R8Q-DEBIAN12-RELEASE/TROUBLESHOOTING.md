## 1. Boot Failure

### Symptom 1.1: Phone Vibrates and Reboots Immediately to LineageOS
- **Root Cause:** Samsung ABL failed to parse the Android Boot Header v2 or rejected section offsets.
- **Diagnostic Check:** Verify byte alignment of `r8q-uefi-boot-complete.img`:
  ```bash
  python3 -c "
  with open('boot/r8q-uefi-boot-complete.img', 'rb') as f:
      magic = f.read(8)
  assert magic == b'ANDROID!', 'Invalid boot magic!'
  "
  ```
- **Remediation:** Ensure the compound boot image was generated by `package_complete_boot_img.py` with 4096-byte page alignment and exact 1660-byte header v2 metadata.

### Symptom 1.2: Screen Stalls on Royal Blue PrePi Header
- **Root Cause:** PrePi reached C runtime dispatch (`PrePi.c`), but could not locate the Linux kernel payload in high DRAM.
- **Diagnostic Check:** Connect Qualcomm GENI UART serial debug cable (115200 8N1) and inspect logs:
  - If log reads: `[R8Q-UEFI] ERROR: Compound container signature not found in Window F`:
- **Remediation:** ABL staged the recovery image at an unexpected DRAM offset outside the tested 176 MiB search range (`0xA0000000`–`0xAB000000`). PrePi candidate scanning table must be updated.

## 2. Kernel Panic

### Symptom 2.1: Screen Freezes on Solid Bright Green Block
- **Root Cause:** PrePi completed cache cleaning and jumped to `0xA2000000`, but the Linux kernel halted during early `head.S` initialization before video console initialization.
- **Diagnostic Check:** Inspect Qualcomm GENI earlycon output:
  - Earlycon parameters: `earlycon=msm_geni_serial,0xa90000`
- **Common Failure Signatures:**
  1. *Bad Translation Table / MMU fault:* Kernel was loaded at an address that was not 2 MiB-aligned. In Project R8Q, destination `0xA2000000` is strictly 2 MiB-aligned (`0xA2000000 % 0x200000 == 0`).
  2. *Unhandled Synchronous Exception at EL1:* DAIF interrupts were unmasked or floating-point register trap was active. Verify `msr cpacr_el1, x1` and `msr daifset, #0xf` executed in `ModuleEntryPoint.S`.
  3. *Kernel BSS Overlap:* Ensure `PrePi.c` zeroed trailing BSS up to `image_size` (`17,235,968` bytes) rather than copying over the ramdisk buffer.

## 3. UFS Storage Detection Failure

### Symptom 3.1: Kernel Prints `ufshcd_wait_for_register: failed` or Storage Times Out
- **Root Cause:** The Qualcomm UFS Host Controller (`1d84000.ufshc`) failed to initialize UFS PHY or link startup timed out.
- **Diagnostic Check:** Verify regulator supplies in kernel log:
  ```
  qcom,sm8250-ufshc 1d84000.ufshc: vcc-supply not ready (-EPROBE_DEFER)
  ```
- **Remediation:** In `sm8250-samsung-r8q.dtb`, ensure PM8150 / PM8150A regulator nodes are referenced correctly. Recall that Project R8Q operates from external MicroSD (`/dev/mmcblk0`); internal UFS initialization failure does not prevent Debian rootfs execution if SD card drivers initialize.

## 4. Device Tree (DTB) Problems

### Symptom 4.1: Kernel Aborts with `OF: fdt: Error -11 processing FDT`
- **Root Cause:** Device Tree Blob corruption, incorrect total size in FDT header, or unaligned memory buffer.
- **Diagnostic Check:** Run `fdtinfo` or Python verification on `sm8250-samsung-r8q.dtb`:
  ```bash
  python3 -c "
  import struct
  with open('kernel/sm8250-samsung-r8q.dtb', 'rb') as f:
      magic, size = struct.unpack('>II', f.read(8))
  assert magic == 0xd00dfeed, 'FDT magic invalid!'
  print(f'DTB valid, total size: {size} bytes')
  "
  ```
- **Remediation:** Ensure `linux,initrd-start` and `linux,initrd-end` nodes written by `fdtput` use 64-bit hexadecimal cells (`-t x 0x0 0xa4400000`).

## 5. Initramfs Mounting & Discovery Failure

### Symptom 5.1: Device Boots to Text Prompt `[R8Q RESCUE SHELL]`
- **Root Cause:** The initramfs could not locate the root filesystem partition (`LABEL=r8q-rootfs`) or virtual disk file (`/r8q-rootfs.ext4`) on the MicroSD card.
- **Diagnostic Playbook in Rescue Shell:**
  1. Inspect enumerated storage block devices:
     ```sh
     ls -la /dev/block/ /dev/mmc*
     ```
  2. If `/dev/mmcblk0` is absent:
     - MicroSD card is not seated properly or SDHCI controller clock gating failed.
     - Reseat the physical MicroSD card.
  3. If `/dev/mmcblk0p1` exists:
     - Check filesystem labels:
       ```sh
       blkid /dev/mmcblk0*
       ```
     - For Mode A: Verify `/dev/mmcblk0p2` has label `r8q-rootfs`.
       ```sh
       e2label /dev/mmcblk0p2 r8q-rootfs
       ```
     - For Mode B: Verify `r8q-rootfs.ext4` exists in root of partition 1:
       ```sh
       mkdir -p /mnt/sd
       mount /dev/mmcblk0p1 /mnt/sd
       ls -la /mnt/sd/r8q-rootfs.ext4
       ```
  4. Manual Pivot Test:
     ```sh
     mkdir -p /newroot
     mount -t ext4 /dev/mmcblk0p2 /newroot
     exec switch_root /newroot /usr/lib/systemd/systemd
     ```

## 6. Debian Root Filesystem Problems

### Symptom 6.1: Systemd Enters Emergency Mode (`welcome to emergency mode!`)
- **Root Cause:** Filesystem corruption on `r8q-rootfs.ext4` or invalid mount entries in `/etc/fstab`.
- **Diagnostic Check:** Mount the ext4 image on host workstation and run `e2fsck`:
  ```bash
  e2fsck -f -v rootfs/r8q-rootfs.ext4
  ```
- **Remediation:** Clean filesystem errors. Ensure `/etc/fstab` does not contain non-existent block UUIDs.

### Symptom 6.2: OpenSSH Daemon Inaccessible over USB CDC-Ethernet
- **Root Cause:** Host computer did not configure IP routing for USB Ethernet interface `usb0`.
- **Diagnostic Check & Host Setup:**
  ```bash
  # On Host Workstation:
  ip link show | grep -E "usb|enx"
  # Assign IP in the 172.16.42.0/24 subnet:
  sudo ip addr add 172.16.42.2/24 dev usb0
  sudo ip link set usb0 up
  ping -c 3 172.16.42.1
  ```
- **Login:**
  ```bash
  ssh r8q@172.16.42.1
  ```
